# Отчёт: регрессия текстур в GLB-экспорте RFMapToolSharp

Дата: 2026-09-05. Среда: Windows, .NET SDK 8.0.424, данные карт `MSH/Map` (43 BSP-карты).

## 1. Диагноз

Проверка по Этапу 1 показала **две независимые проблемы**, ни одна из них — не в конвейере DDS→PNG→GLB:

### 1.1. HEAD репозитория не компилируется (главная находка)

Коммит `26cf98a feat(tools): add RF candidate resource root probe` добавил в `Program.cs`
~1670 строк GLB→RF-функционала, который вызывает `R3MMaterialFile.Save()` и `R3TFile.Save()` —
эти методы **никогда не были реализованы** (`git log -S "public void Save"` пуст).
Итог: свежая сборка падала с CS1929, и любые локальные попытки «починить» сборку были
потенциальным источником наблюдаемой регрессии текстур.

### 1.2. Сам текстурный конвейер в коде HEAD исправен

Эталонный exe (bin от 21.08) и свежесобранный HEAD (после фикса 1.1) дают **идентичный результат**:
Sette — 81 image, 205/206 материалов с BaseColorTexture; Cauldron01 — 178 images, 305/306.
Извлечённые из GLB PNG визуально корректны (проверено глазами, `s_desret_*.dds` 256×256).

Проверки по списку подозреваемых причин:

| Причина из плана | Статус |
|---|---|
| А. Пути к R3T | Не подтверждена: на всех 43 картах `.r3t` найден и прочитан |
| Б. Pfim не поддерживает формат | Не подтверждена: 0 реальных ошибок декодирования |
| В. ImageSharp encode | Не подтверждена: добавлена round-trip перечитка PNG — все валидны |
| Г. SharpGLTF API | Не подтверждена: версии пакетов в `.csproj` не менялись с первого коммита |
| Д. UV-координаты | Вне симптома (текстуры на месте) |

## 2. Патчи (что изменено в коде)

1. **`Parsing/Textures/R3TFile.cs`** — реализован `Save(path)` (симметричен `Load`).
2. **`Parsing/Materials/R3MMaterialFile.cs`** — реализован `Save(path)` (симметричен `Load`).
   → Проект снова собирается, GLB→RF repack-функционал разблокирован.
3. **`Export/TextureDiagnostics.cs`** (новый) — сборщик диагностики Этапа 1 + писатель `texture_report.json` (Этап 3.1).
4. **`Export/TextureConverter.cs`** — лог `[CONV]` со sniffing'ом формата DDS (DXT1/3/5, ATI1/2, BC7, DXGI);
   вместо ложной эвристики «PNG < 256 байт» — **валидация перечиткой** PNG через ImageSharp (Причина В из плана).
5. **`Export/GltfExporter.cs`** — логи `[GLTF]` по каждому материалу (Surface→TexId→имя текстуры, Embedded, статус);
   убрано молчаливое проглатывание ошибок конвертации; сводка + запись `texture_report.json` в конце экспорта.
6. **`Program.cs`** — логи `[TEX]` (путь, Exists, размер, mtime, fallback на другой .r3t, список имён текстур);
   batch-флаги Этапа 3.3: `--all`, `--filter=Маска*`, `--resume`; validation hook Этапа 3.2: `--validate`
   (round-trip загрузка GLB, exit code 0/1/2); фикс краша `--bsp-dump` на бесконечных float
   (`AllowNamedFloatingPointLiterals`).
7. **`README.md`** — документация новых флагов и диагностики.
8. **`global.json`** (новый) — закреплён SDK 8.0.424, чтобы preview-SDK 10.0.400 не подхватывался по умолчанию.

Примечание по окружению: в текущей shell-сессии сборка требует переменной `ProgramData`
(в минимальном окружении её нет, и NuGet падает с `Value cannot be null (Parameter 'path1')`
в `XPlatMachineWideSetting`). В обычной сессии Windows/Visual Studio проблема не воспроизводится.

## 4. Остаточные проблемы (не регрессия текстур)

1. **Dungeon00** — карта 2004 года: пул FVertex содержит мусорные/бесконечные значения
   (старый вариант сжатых вершин R3Engine), `RealFaces` пуст → GLB без геометрии и материалов.
   Это ограничение BSP-парсера, а не текстурного конвейера. Нужен отдельный анализ
   (вероятно, иная схема упаковки вершин в ранних версиях формата).
2. **Mojibake** в комментариях `Program.cs` / `Parsing/Collision/BspFile.cs` (Этап 3.6) — частично
   исправлено в тронутых блоках, полная конвертация в UTF-8 не делалась.
3. **ImageSharp 3.1.7** — NU1902 warning сохраняется; обновление до 3.1.8+ рекомендовано, но не
   выполнялось (нет доступа к NuGet в этой сессии, а рисковать регрессией не стал).
4. Этап 3.4 (SPT real models), 3.5 (material reconstruction), unit-тесты парсеров — не в scope этого прогона.

## 5. Как воспроизвести проверку

```bash
set ProgramData=C:\ProgramData   # только если shell без стандартного окружения
dotnet build
cd MSH
..\bin\Debug\net8.0\RFMapToolSharp.exe --map Sette --validate
..\bin\Debug\net8.0\RFMapToolSharp.exe --all --validate --resume
```

Логи прогонов: `_runs/batch_run1.log`, `_runs/batch_run2.log`;
образцы встроенных текстур: `_runs/sette_tex_0..2.png`; дамп Dungeon00: `_runs/d00dump.json`.
